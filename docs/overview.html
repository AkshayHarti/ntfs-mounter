What is built, how to run it, and how to know it works

A read-write NTFS stack for macOS, wrapped around one guarded core: eight CLI commands, a root-run dashboard, an agentic surface, a read-only MCP server, and a menu-bar app. 407 tests, four distribution channels, and exactly one step that still needs a real disk.

01 · what has been built

Four surfaces, one guarded core

Every surface funnels through the same orchestration module, so a generated button, an MCP client, or a menu-bar click cannot reach a disk without passing the same guards.

02 · how to operate

One path, four ways in

Install once, verify the host, then mount → write → unmount. The CLI, the dashboard, the agent, and the menu bar all run these same steps through the core.

Commands

  • Check the hostntfsmnt doctor
  • List volumes and statentfsmnt list
  • Mount read-writesudo ntfsmnt mount HD1
  • Unmount (busy → SIGTERM once)sudo ntfsmnt unmount HD1
  • Open the dashboardsudo ntfsmnt web
  • Read-only MCP over stdiontfsmnt mcp

What root may do

Root is requested through one sudo re-exec. The optional privileged install grants a NOPASSWD rule for web only — mount, unmount, and eject run inside the already-root server.

No osascript, so the terminal keeps its Full Disk Access attribution.
