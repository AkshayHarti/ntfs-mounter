Read-write NTFS on macOS, from the command line.

ntfsmnt replaces Apple’s read-only NTFS mount for one volume at a time with an ntfs-3g mount served by FUSE-T: no kernel extension, no SIP change, no reboot.

395 tests · MIT licence · Python ≥ 3.12 · macOS only, verified on Apple Silicon (macOS 26.5.2)

From a checkout

git clone https://github.com/AkshayHarti/ntfs-mounter.git && cd ntfs-mounter && ./scripts/setup.sh

Installs the native prerequisites — the FUSE-T cask and an ntfs-3g built and linked against it — then prints the Full Disk Access reminder. Idempotent: satisfied steps are skipped, and ./scripts/setup.sh --check reports state without changing anything. From the same checkout, uv sync --extra web gets the tool itself.

From PyPI

uv tool install "ntfsmnt[web]"

The CLI and the local web UI, installed from PyPI. pipx install "ntfsmnt[web]" is the equivalent; drop [web] for the CLI alone. The native prerequisites from the first option are still required.

From npm

npx ntfsmnt --help

A dependency-free proxy: it finds the real Python CLI and hands it your arguments, or falls back to uvx --from "ntfsmnt[web]". It reimplements nothing; the native prerequisites are still required. The first npm publish lands on the next v* tag.

Homebrew

brew tap AkshayHarti/ntfs-mounter https://github.com/AkshayHarti/ntfs-mounter && brew install AkshayHarti/ntfs-mounter/ntfsmnt

The tap lives inside this repository rather than a separate homebrew-* one, so it has to be tapped by URL. The formulas need the FUSE-T cask; run brew install --cask fuse-t first if it is not installed, and on Homebrew 7+ trust the third-party tap once with brew trust --tap AkshayHarti/ntfs-mounter.

The problem

macOS mounts NTFS volumes read-only. Its built-in FSKit driver is the safe default, and for most people it is the end of the story — until a disk formatted on Windows needs a file written to it.

The usual answers are to pay for a commercial driver or to trust a hand-rolled bundle of binaries. The first costs money and is not open source. The second is a way to lose data: an NTFS driver runs with enough privilege to corrupt a filesystem when the mount options, the device, or the teardown are wrong.

Nothing here touches a drive without an explicit command. There is no daemon and no launch agent: a volume is mounted, unmounted, or ejected only when you ask for it — in the terminal, or with a button in the local web UI.

Scope, stated plainly: verified on Apple Silicon running macOS 26.x. Intel Macs are untested, and Windows, Linux, and non-NTFS filesystems are out of scope.

The solution

One implementation, two front ends. The CLI and the web UI take the same snapshot of the system, enable the same actions, and call the same mounter and unmounter code — so there is no second implementation to drift.

mount
Evicts Apple’s read-only mount, starts ntfs-3g on FUSE-T, and proves the result writable before reporting success.
unmount
Tears down the FUSE-T mount, then restores Apple’s read-only mount — the state you started in. --keep-unmounted stops after the unmount.
eject
Unmounts and ejects the parent disk, refusing while a mount it cannot account for is still live.
doctor
Checks FUSE-T, the ntfs-3g linkage, root, and whether the first NTFS device can be opened, with a fix for each failure.
status
Reports one volume’s state, driver, and serving process, as text or JSON. list does the same for every attached NTFS volume.

The optional web UI — the web subcommand, started as root — shows the same volumes and performs the same mount, unmount, and eject actions. It binds 127.0.0.1 only, prints its URL with a one-time token, and holds itself to the same safety rules as the CLI.

Design

The interesting part of a tool like this is what it refuses to do. These are the invariants the code enforces; they are written down in AGENTS.md and are not negotiable in a change.

  • One escalation path, one exception. Every mutating command re-execs the CLI through sudo in privileged.py. There is no osascript, no GUI password prompt, and no other route to root — except the menu-bar app, which starts web under a NOPASSWD rule that names one root-owned binary and one subcommand. It is opt-in at install and removed by the same installer.
  • A failed mount puts Apple’s read-only mount back. The mounter evicts that mount to make room, so every failure path restores it, and the tool claims “restored” only when a fresh mount-table read confirms it.
  • The FSKit mount point is recreated. Unmounting Apple’s FSKit volume also deletes /Volumes/<label>. The mounter recreates the directory before ntfs-3g starts, because FUSE-T’s helper fails with exit 66 when the mount point vanishes underneath it.
  • One signal, once. The only signal the unmounter ever sends is SIGTERM, once, to the serving ntfs-3g after a normal unmount fails as busy. It retries the unmount and then reports; it never sends SIGKILL.
  • The web UI is loopback-only, and guarded. It listens on 127.0.0.1; the launch token is compared in constant time and exchanged once for an HttpOnly, SameSite=Strict cookie. Every mutation needs the X-NTFSMNT: 1 header and an allowed Origin; a Host outside the allow-list gets 421; and a single non-blocking operation lock per server process answers a second request with 409.
  • No write without a probe. A mount is proven by writing .ntfsmnt-probe, reading it back, and deleting it — then checking the mount point is owned by the invoking user, not root, before success is reported.
  • Hibernated and dirty volumes are refused by default. --recover replays the NTFS journal and --remove-hiberfile discards a hibernated Windows session; both are opt-in, and the second requires typing the volume label first.
  • No guesses on duplicate labels. If two volumes share a label, the command fails and lists the candidates instead of picking one.
  • No repair tools, ever. The code never calls ntfsfix, ntfsresize, mkntfs, or ntfswipe — not as a fallback, not as a convenience.

How to run

Two native pieces are required on every Mac: the FUSE-T cask, and an ntfs-3g built against it rather than against macFUSE. The setup script installs both; start with the read-only check, which changes nothing and exits cleanly on a machine that is missing everything.

./scripts/setup.sh --check

Then install the tool by any of the four routes above and ask it what the host is missing:

ntfsmnt doctor

mount, unmount, and eject re-exec through sudo, which is why the terminal you run them from needs Full Disk Access — the grant is attributed to the terminal, not to the binary. Run doctor unprivileged to inspect the environment; its root and device-access checks fail by design there, and pass under sudo from the same terminal.

For the browser UI, from a checkout:

sudo uv run ntfsmnt web

It prints http://127.0.0.1:<port>/?token=<random> and serves nothing outside loopback. The installed command is the same web subcommand, run as root.

For the no-Terminal route, install the menu-bar app once and use it from then on:

bash scripts/install-app.sh --launch

Click Set up… once (one password), grant Full Disk Access to ntfsmnt.app (click + in the pane — macOS does not list it by itself), then Start dashboard. Setup writes a root-owned CLI at /usr/local/libexec/ntfsmnt and a sudoers rule that names web only; the same installer removes both with --uninstall.

Future work. The menu-bar app is unsigned. Notarization needs an Apple Developer ID; the walk-through is in docs/APP.md. A LaunchDaemon or XPC privileged helper is deliberately not used.

Audience

  • The maintainer’s other Macs. One documented sequence, no memory required: clone, run the setup script, mount.
  • Technical Mac users. uv tool install, pipx, or Homebrew, plus a setup script that builds the one dependency macOS does not ship.
  • The open-source community. An MIT-licensed PyPI release with tests, issue tracking, and design specs and plans kept in the repository.
  • Non-technical users, mostly. Install the menu-bar app (bash scripts/install-app.sh), click Set up… once, grant Full Disk Access, then Start dashboard: no Terminal and no password afterwards. The app is unsigned and built from source; a notarized download still needs an Apple Developer ID.

Contribute

Development uses uv. The web extra brings in FastAPI, uvicorn, and Jinja2 for the browser UI and its tests; without it those tests skip while the service, model, and config tests still run.

uv sync --extra web
uv run pytest -q

That is 395 tests. The important ones use the injected-runner pattern: every subprocess effect goes through an injected callable (run, read_mount_table, sleep, the write probe), so the full mount and unmount sequences run without touching /Volumes. The npm proxy has its own node:test suite, run by CI.

The safety invariants and the web-layer invariants live in AGENTS.md. A good change adds tests in that injected-runner style and keeps the README and AGENTS.md honest about what is verified and what is not.

Bugs and proposals go to GitHub Issues; the specs and plans behind each feature are in docs/.
