Mount your NTFS disk, step by step.

Six steps from a fresh Mac to a writable disk, using your own volume label. The page builds the commands; you run them. It cannot see your hardware, and it will not pretend to.

macOS only · no kernel extension · no SIP change · no reboot

This page cannot see your disk. Everything it shows comes from what you paste below, plus the steps you mark done. Where it guesses, it says so.

  1. 0 Is this your machine?

    done

    Three requirements, and one of them is a real permission prompt.

    • A Mac. Verified on Apple Silicon running macOS 26.5.2. Intel is untested.
    • Your admin password, once. The setup script calls sudo to install ntfs-3g; the FUSE-T installer asks for a password itself.
    • Full Disk Access (FDA). Reading a raw disk device needs it. Grant it to your terminal app in System Settings → Privacy & Security → Full Disk Access. Without it, the mount fails with a permission error that looks like a bug.

  2. 1 Install

    done

    Prerequisites first, from a checkout. It is idempotent; satisfied steps are skipped.

    git clone https://github.com/AkshayHarti/ntfs-mounter.git && cd ntfs-mounter && ./scripts/setup.sh

    To see what is missing without changing anything, run ./scripts/setup.sh --check first.

    Then the tool itself:

    uv tool install "ntfsmnt[web]"

    Check that everything is reachable:

    ntfsmnt doctor
    One of the doctor checks failed

    doctor reports four things: FUSE-T present, ntfs-3g linked against FUSE-T, root, and device-access.

    Run unprivileged, the root and device-access checks fail by design. That is not a problem to fix. A missing FUSE-T, or an ntfs-3g that is not linked against it, is.

    Clicking this records your word, not a check. This page did not run anything.

When the mount refuses

The tool prints one sentence that names the cause, then stops. Here is what each sentence means, and the one thing this page will not do about it.

Hibernated

The volume is hibernated. Re-run with --remove-hiberfile to discard the hibernation file and mount it.

The disk was left by Windows Fast Startup or hibernation, and one file on it holds a memory image that must not be overwritten.

What to do: boot Windows on that machine and shut it down fully — hold Shift while clicking Shut down, or disable Fast Startup. Then mount again.

Dirty

The volume is marked dirty. Re-run with --recover to let ntfs-3g replay its journal and mount it.

Windows did not finish writing, so the filesystem's journal has unfinished work in it.

What to do: if the data matters, let Windows run its own check on the disk first. --recover replays the journal; it is a recovery step, not a repair, and this page will not generate it for you.

Busy

The volume is already mounted or files on it are open. Unmount it or close those files, then try again.

Something else holds the volume: Finder, a backup, an editor with a file open.

What to do: close the files, then run ntfsmnt unmount <label> and try the mount again.

Permission denied

Permission denied opening the disk. Grant Full Disk Access to your terminal app in System Settings > Privacy & Security, then try again.

Full Disk Access is missing, or was granted to a different terminal app than the one you are using.

What to do: add the exact app you are typing in — Terminal, iTerm, VS Code — then quit and reopen it. macOS does not apply the change to a running process.

Paste what the terminal printed

The page matches the tool's own sentences. Nothing is uploaded and nothing is stored.

The two flags you should not copy from a blog post. --recover replays the filesystem journal. --remove-hiberfile deletes a hibernation file that may hold unsaved work. Both exist, both are deliberate, and neither is generated anywhere on this page or reachable from the MCP tools. If you need them, run them yourself after reading what they discard.
